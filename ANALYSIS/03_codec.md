## 1. 数据位置与解密

`briefing_dat_load` @ `0x1400A5570`（反编译 + 汇编核对 `0x1400A5669`）：

```asm
1400A5656  mov     rcx, cs:off_140EA4220      ; "009645fa.PDT"（表首项）
1400A565D  add     rcx, 0B60h                 ; +2912 = 第 14 项
1400A5664  call    name_hash                   ; -> name_hash("0076531d.DAT")
1400A5669  mov     edx, cs:dword_14117C094
1400A5672  mov     rcx, cs:qword_14117C098
1400A5679  shl     edx, 0Ch
1400A567C  call    buffer_xor_decrypt
```

`key = name_hash("0076531d.DAT") = name_hash("0076531d") = 0xC4CECBE0`。

`sub_1408C57D0` @ `0x1408C57D0` 建立名为 `"codec thread"` 的线程
（`0x140D7D9B8`），是 CODEC 子系统的入口，佐证本文件即 CODEC 数据。

### 1.1 磁盘上是**逐扇区（4096 字节）分别加密**——实测

每个扇区都用 `buffer_xor_decrypt(sector, 4096, key)`（内部
`mt_seed(key)` + `mt_advance(20)`），密钥流只与**扇区内偏移**有关。

`_probe_bri8.py` 的 A/B 判决：

| 判据 | A 逐扇区 4096 | B 连续 16384 |
|---|---|---|
| 512 字节窗口 UTF-8 可解码数 | **1519** | 579 |
| `file+0x1700` 处内容 | 记录头魔数 `6f 45 62 4e` + 合法偏移表 | 乱码 |
| 扇区 1/2/3 的 printable 比 | 0.239 / 0.133 / 0.149 | 0.280 / 0.389 / 0.381（≈随机 0.371） |

**块内偏移的证否**（`_probe_bri17.py`）：曾怀疑"块起点任意、块内第 k 个扇区
用 keystream 偏移 `k*4096"`，对全部 1011 个扇区 × k=0..3 逐字节走 UTF-8 状态机：

| k | 平均文本性 | 全文件魔数总数 |
|---|---|---|
| **0** | **0.7700** | **2759** |
| 1 | 0.5549 | **0** |
| 2 | 0.4511 | **0** |
| 3 | 0.4387 | **0** |

k>0 在全文件**一个魔数都没有**，故"每个扇区都用 keystream 偏移 0"成立。
（个别扇区在 k=1 下开头会解出一小段连贯文本，属局部巧合——该扇区 k=1 的
文本性仅 0.4949，远低于 k=0 的 0.8564。）

### 1.2 疑点（**未验证，不得当结论**）

`briefing_dat_load` 里解密长度是 `dword_14117C094 << 12`，而

```asm
14080426D  lea     r8d, [rsi+1]     ; rsi = req >> 24
140804274  shl     r8d, 0Eh
14080427B  shr     r8d, 0Ch         ; == (HIBYTE(req)+1) << 2  -> 恒为 >= 4
```

即请求/解密的粒度是 **≥ 4 个扇区**，与 §1.1 的逐扇区事实矛盾。
逐扇区解密应发生在 op=7 的 I/O 工作线程里（`sub_14045DF30(req, 7, ...)`
@ `0x14045DF30`，经 `sub_1401208C0` → `sub_14008B240`），该函数尚未定位。

## 2. 记录头（28 字节，起点 16 字节对齐）

直接来源是 `sub_1400A3230` @ `0x1400A3230`：

```c
dword_141103D48 = a1[0] | a1[1]<<8 | a1[2]<<16;   // 仅 a2==0 时
for (i = (u32*)(a1+4); *i != -1; ++i) v5++;       // -1 结尾的 u32 数组
v7 = i + 1;  ...  *v7 = v4;                       // +8 是运行时计数槽
v10 = (u8*)(v7 + 1);                              // == a1 + 12 + 8*v5
v11   = v10 + u32@(v10 + 0);
v3[1] = v10 + u32@(v10 + 4);
v3[2] = v10 + u32@(v10 + 8);
v3[3] = v10 + u32@(v10 + 12);
```

| 偏移 | 类型 | 含义 |
|---|---|---|
| `+0x00` | u24 | 记录头魔数 `0x62456F`；与 `+0x03` 合成 `6f 45 62 4e`（**全部 2,663 条记录相同**，不是 id） |
| `+0x03` | u8 | 魔数第 4 字节 `0x4E`（全部记录相同） |
| `+0x04` | u32 | `0xFFFFFFFF` —— u32 数组的终止符；本文件**所有记录该数组为空**，`v5 = 0` |
| `+0x08` | u32 | 运行时计数槽，运行时被写 0；磁盘值无意义 |
| `+0x0C` | u32 | `off0` → 脚本区 `v11` |
| `+0x10` | u32 | `off1` → **u32 偏移表** `v3[1]` |
| `+0x14` | u32 | `off2` → **UTF-8 文本池** `v3[2]` |
| `+0x18` | u32 | `off3` → `v3[3]`（4 字节，内容多为 0，语义未验证） |

记录按魔数 `REC_MAGIC = 6f 45 62 4e` 在 16 字节栅格上扫描得到；
`idx = off / 16`，正是 `sub_140804080` 里的 `16 * LOBYTE(req)`。

### 2.1 剔除魔数碰撞的假阳性（关键）

单靠"偏移表递增 + 串可解码"会放过 601 条假阳性（随机数据里碰巧出现
`6f 45 62 4e`，偏移字段是随机大数）。决定性判据是**脚本区入口必须是合法
字节码**——`sub_1400A3040` 从 `A->entry` 起先执行一条包裹指令，
其 opcode 必须是 `0x8d` / `0x8e`（`sub_1400A4770` 的 case 13/14）。

`_probe_bri18.py` 的交叉表：

| | 台词全可解码 | 台词含乱码 |
|---|---|---|
| 入口 opcode 合法 | **2049** | 0 |
| 入口 opcode 非法（多为 `entry_off` 越界） | 13 | **601** |

两条判据**完全一致**，故以入口合法性为最终筛选条件。剔除后
2,049 条记录的台词 **100% 可 UTF-8 解码**（0 个替换字符）。

## 4. 脚本区与字节码

```
v11   = v10 + off0
pool  = v11 + 4        -> xmmword_141103D70（A->pool）
entry = v11 + u32@(v11) + 8   -> sub_1400A3040 读取后交给解释器
tbl   = a1 + 4         -> xmmword_141103D60（A->tbl）
```

`sub_1400A4770` @ `0x1400A4770` 解码操作数：

```c
switch (*a1 & 0xF) {
  case 13: *a2 = u8@(a1+1);  return a1 + 2;
  case 14: *a2 = u16@(a1+1); return a1 + 3;
  case 15: *a2 = u24@(a1+1); return a1 + 4;
  default: *a2 = *a1 & 0xF;  return a1 + 1;
}
```

`sub_1400A35C0` @ `0x1400A35C0` 是解释器，按 `op & 0xF0` 分派：
`0x30` 文本、`0x60` 按 u24 id 查 `qword_141103DF0` 处理器表并回调、
`0x70` 按 id 调子程序（`v9 = sub_1400A3980(id | (dword_1410A23E0 << 24))`），
`op & 0xF0 == 0` 结束。

**实测**：入口是一条 `0x8e` / `0x8d` 包裹指令（长度 178~382），
其 payload 内是逐条台词的 `0x6d` 指令（长度 25，u24 id `0x3B91EB`），
参数里第 7 字节是 0 起的行号。示例（记录 0）：

```
0x60c  8e len=382   (包裹)
0x60f  6e len=378   id=0x57C8D1
       ... "v_bri_kaz0010_000_0\0"
0x62e  6d len=23    id=0x3B91EB  07 06 e6 dc 28 0e 00 00 ...   <- 行 0
0x647  6d len=23    id=0x3B91EB  07 06 34 3a 46 0e 01 00 ...   <- 行 1
0x660  6d len=23    id=0x3B91EB  07 06 34 3a 46 0e 02 00 ...   <- 行 2
```

> 各参数的语义（时间轴、说话人、镜头等）**尚未反完**。

## 7. 语言归属 —— **未解决**

`lang_get_language_id()` @ `0x140027B40` 已取证（读 `g_launcher_config[13]`）：

| 返回值 | 启动器语言 |
|---|---|
| 0 | `en` |
| 1 | `fr` |
| 2 | `gr`（德语） |
| 3 | `it` |
| 4 | `sp` / `pt` |
| 6 | `jp`、空、未知 |

但**语言不在记录里**，已取得的证据：

1. **记录头里没有语言字段**：各扇区段的记录头逐字节同构，只有长度字段不同
   （`_probe_bri12.py` §6）。
2. 语言体现在**寻址参数**上：请求字
   `idx(bit0-7) | 扇区(bit8-23) | (页数-1)(bit24-31)`
   （汇编 `0x14080422A`/`0x140804271`/`0x14080427B`），由
   `sub_1408045E0(ctx, a2)` 的 `a2` 提供。
3. `sub_1405E06E0` @ `0x1405E07CB` 处
   `edx = dword_141495DE0[rcx]` 是运行时表，但**静态内容为全 `0xFFFFFFFF`**
   （运行时填充，填充来源未定位）；且 `rsi` 是 imagebase
   （`lea rsi, cs:140000000h`），**不是**语言索引。
4. `sub_14007BE00` @ `0x14007BE00` 的筛选量 `dword_1410A26F8` 由
   `sub_14007BDE0(1574688)` 在 `sub_1400CA720` 两处赋值，**均为常量**
   `0x180A20`，与语言无关（是块类型标签）。

**曾尝试并被证伪的假说**（记录备查，勿再用）：
"文件按语言分成 6 个连续扇区段，同一段对话在 6 段各存一份"。
用语音 ID 做跨段重叠检验：段间 Jaccard 仅 0.55–0.67，
且跨段共享语音 ID 的记录**台词条数 0/200 一致**，假说不成立。

**因此本模块不输出语言列**。`Record.script_class()` 只陈述 Unicode
层面的客观事实（`kana` / `latin` / `-`），不是语言判定。
